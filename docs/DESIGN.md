# 设计文档

本文记录 shushu-s-harmonica 的设计目标、关键约束、架构、算法与取舍，便于后续维护和二次开发。

## 1. 背景与目标

三角洲行动的口琴是单音乐器：自然音键为 `Z X C V B N M ,`，按住鼠标左键降八度、右键升八度、中键升半音，长按可以持续发声；游戏内建的 `R` 自动演奏只覆盖已解锁的曲目。

本项目的目标是：**把任意 MIDI 或简谱转换成这套键鼠输入，在桌面层自动演奏，并保证可随时安全停止。**

成功标准：

1. 键位映射与游戏实际行为完全一致，包括最高音区的特殊规则。
2. 节奏稳定，能够表达连音、断奏和长音。
3. 失焦、停止和异常退出播放时清理模拟输入，并报告释放失败。
4. 在没有 Windows 的开发机上也能验证曲谱解析、映射与时序。
5. 使用者不需要理解内部实现即可完成选曲、试运行、实机演奏。

## 2. 非目标

- 不注入游戏进程、不读写游戏内存、不修改网络封包、不使用驱动级输入。
- 不做复音/和弦演奏，不模拟多个口琴同时发声。
- 不做音频合成或试听。
- 不自动切换游戏窗口、不模拟点击游戏 UI。
- 不绕过游戏内曲谱解锁机制，仅演奏用户自备的 MIDI/简谱。
- 不保证规避反作弊检测；使用风险由使用者承担。

## 3. 键位与时序约束

| 约束 | 实现 |
|---|---|
| 游戏可用音域为 MIDI 48–85（C3–C#6） | `RANGE_LOW=48`、`RANGE_HIGH=85` |
| C5 用逗号键，C#5 加中键，C6 加右键，C#6 加右键和中键 | `to_action` 对 `pc in (0,1)` 且高八度时特判 |
| 升半音使用下方自然音 + 中键 | `_SHARP_BASE` 映射 |
| 音键按下前预留 12ms 准备修饰键 | `PREP_MS=12` |
| 最短按键保持 40ms | `MIN_HOLD_MS=40` |
| MIDI 和 TXT 的尾隙均为 20ms | `DEFAULT_GAP_MS=20` |
| 固定预备、保持和尾隙合计 72ms | `build_play_notes` 按播放速度换算可用时长，跳过不足 72ms 的音 |
| 按住音键时改变修饰键会重新触发音符 | 每个音独立使用修饰键，音键松开后才释放修饰键 |
| 播放操作避开游戏使用的单键 | 使用 `Shift+F8/F9/F10` |

键位和时序参数集中在 `core/mapping.py` 与 `core/engine.py`，方便实机校准。

## 4. 总体架构

```text
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  score.py    │────>│  mapping.py  │────>│  engine.py   │
│ MIDI / TXT   │     │ 音高→按键计划 │     │ 演奏调度线程  │
└──────────────┘     └──────────────┘     └──────┬───────┘
                                                  │
                     ┌────────────────────────────┼────────────────────────────┐
                     ▼                            ▼                            ▼
          ┌────────────────────┐      ┌────────────────────┐      ┌────────────────────┐
          │ input_backend.py   │      │ hotkeys.py         │      │ ui/main_window.py  │
          │ SendInput / DryRun │      │ 全局热键消息循环    │      │ Qt 主线程 + 信号桥  │
          └────────────────────┘      └────────────────────┘      └────────────────────┘
```

分层原则：

1. **解析层**输出带绝对时间的 `ScoreEvent`，保留 MIDI 和弦里的候选音。
2. **映射层**按速度筛选音符、应用移调，并生成与设备无关的 `PlayNote` 计划。
3. **调度层不关心设备实现**：只依赖 `InputBackend` 抽象。
4. **输入层不关心音乐**：只负责发送扫描码/鼠标事件、前台检测和释放。
5. **UI 层**通过 Qt 信号接收解析结果、状态、进度与日志。独立的急停热键线程可直接通知演奏线程取消。

## 5. 数据模型

```python
ScoreEvent(pitch, start, duration, velocity=80, alternatives=())
Score(name, events, length)                       # length 包含曲末休止
PlayNote(start, duration, key_index, shift, sharp) # 与设备无关的按键计划
```

- 时间一律使用秒，`start/duration` 为音乐时间（不受暂停影响）。
- `key_index`：0–6 对应 `Z`–`M`，7 对应 `,`。
- `shift`：−1 降八度、0 原调、+1 升八度；负数对应鼠标左键，正数对应右键。
- `sharp`：是否需要中键（升半音）。

## 6. 曲谱层设计

### 6.1 MIDI

- 支持使用 PPQ 计时的 type 0 / 1。type 2 与 SMPTE 计时会抛错。
- 跳过 channel 10（index 9，打击乐）。
- `note_on` 且 velocity > 0 为按下；`note_off` 或 velocity = 0 的 `note_on` 为松开。
- 按轨道、通道和音高匹配按下与松开。重复按下时先结算前一个音，避免状态覆盖。
- 各轨道的事件按绝对 tick 排序，共用速度变化时间轴。
- 文件结束时仍未松开的音按 0.5 秒收尾，避免因缺失 `note_off` 丢失旋律。
- 单音化算法：
  1. 按起点排序，以每簇第一个音为基准合并起点相差小于 30ms 的音。
  2. 每簇按音高排序，保留较低音作为备选。
  3. 生成计划时，把每个候选音最晚截到下一簇起点，按速度计算可用时长。优先选择能够演奏的最高音。整簇无可用音时，记为一次跳过。

### 6.2 简谱 TXT

语法（UTF-8）：

```text
TITLE=曲名
BPM=100

[注释 // ...]  音符 token 以空白或 | 分隔
```

- 音符：`1`–`7`，`0` 休止，`8`/`i` 为高音 `do`（音级 1 升八度）。
- 前缀：`b` 降八度（可叠加）、`^` 升八度（可叠加）、`#` 升半音。
- `GRID` 指定一拍内的时值单位数，默认 1，整数范围按 1–16 处理。每个音符或休止占一个单位，每个后缀 `-` 再增加一个单位。单独的 `-` 延长前一个音符或休止一个单位。
- 无法识别的记号会报告行号与原记号，整首没有音符也会报错。识别到 `@format` 或键位文本谱时，提示改用受支持的曲谱格式。
- `BPM` 可省略，默认 100。显式填写时，有限数值限制在 20–300 后取整，非法值报告行号。

### 6.3 边界处理

- `TITLE` 为空时使用文件名。
- 文件不存在或编码错误会在曲谱信息区显示。
- TXT 长度取最终游标位置。MIDI 长度取轨道终点与最后一个音的末尾中较晚者。两种格式的曲末休止都会计入时长和循环。

### 6.4 联网曲库更新

- 更新源固定为 GitHub 仓库 `DamonBBQ/shushu-s-harmonica` 的 `main` 分支 `scores/` 目录，通过 HTTPS Contents API 获取文件名、大小和 Git blob SHA。
- `scores/.git-scores.json` 是曲目归属清单。只有清单内的文件属于 Git 内置曲目，允许被联网更新覆盖；未列入清单的文件视为本地曲目，即使与远端同名也跳过并报告保留。
- 远端新增且本地不存在的曲目可以安装，成功后自动加入归属清单；清单缺失时不会覆盖任何已有文件，清单损坏则停止更新。
- 本地 Git 曲目按 Git blob 规则计算校验值；Windows 检出的 TXT 会将 CRLF 规范化后比较，避免把换行差异误判为曲谱更新。
- 下载进入曲库下的临时目录，逐文件核对大小与 Git blob SHA，并调用 `load_score` 试解析。全部通过后才开始替换，任何校验或解析失败都不会覆盖原文件。
- 替换前将已有同名文件和归属清单复制到 `scores/.update-backups/<时间戳>/`，随后用 `os.replace` 原子替换；安装中途失败会回滚已处理文件。
曲库更新只处理曲谱数据和归属清单。网络请求与文件安装运行在后台线程，Qt 主线程只接收进度和结果信号。

### 6.5 完整程序更新

- 仅 Windows 的 PyInstaller 冻结模式启用完整更新。程序版本由 `core/version.py` 统一提供，更新源为同一仓库的最新 GitHub Release。
- 发布资产必须命名为 `HarmonicaPlayer-<版本>-windows-x64.zip`，并附带同名 `.sha256` 文件。ZIP 顶层为 `HarmonicaPlayer/`，其中包含 EXE、`_internal/`、`app-version.txt` 和 `scores/`。
- 下载使用流式写入和独立大小上限，核对 Release 声明大小及 SHA-256。解压拒绝路径穿越、绝对路径、符号链接、重复文件名和过量解压数据，并验证版本标记与运行依赖。
- 暂存目录位于程序目录同级。合并曲库时，以旧 `.git-scores.json` 判断归属：清单内内置谱采用新包，清单外本地谱复制进新包；本地同名文件优先保留，并从新清单移除其 Git 归属，避免下次被误覆盖。既有 `.update-backups/` 一并保留。
- 用户确认后启动带 BOM 的 Windows PowerShell 更新助手。助手等待原进程退出，将旧程序目录移为同级备份，再启用新目录并重启；替换或重启失败时恢复旧目录。失败日志位于程序目录旁的 `.HarmonicaPlayer-update.log`。
- 更新过程中禁止演奏和切窗。退出前同步 QSettings、停止演奏并注销热键。源码模式不下载或执行程序更新包。

## 7. 映射层设计

### 7.1 音高到按键

基础音级：

```text
pc : 0  2  4  5  7  9  11
键 : Z  X  C  V  B  N  M     (index 0–6)
```

八度修饰：

```text
shift = octave − 4          # octave = pitch // 12 − 1（科学音高记号）
shift < 0 → 左键；shift > 0 → 右键
```

升半音：

```text
pc 1 (C#) → Z + 中键      pc 3 (D#) → X + 中键
pc 6 (F#) → V + 中键      pc 8 (G#) → B + 中键
pc 10 (A#) → N + 中键
```

最高音区特判：

```text
if pc in (0, 1) and octave > 4:
    C5  → 逗号
    C#5 → 逗号 + 中键
    C6  → 逗号 + 右键
    C#6 → 逗号 + 右键 + 中键
```

C6 比 `Z` 对应的音高两个八度，游戏的右键只能升一个八度，因此从逗号键对应的 C5 升八度得到 C6。

### 7.2 移调与折叠

1. 根据当前速度筛选可用时长至少 72ms 的音，再统计这些音应用手动移调后的音高。
2. 自动移调从 −30 到 +30 半音搜索，利用音高计数选出落进 48–85 的音最多的方案。命中数相同取绝对值较小的自动值。
3. 实际移调 = 手动值 + 自动值。超出 48–85 的音按 ±12 折返，保留音级并改变八度。

### 7.3 为什么先整体移调再折叠

逐音折叠会破坏旋律的相对音程；整体移调可以保持旋律轮廓。只有少数极端音才需要单独折返，此时至少大部分音符仍保持原调。自动移调让整首曲子「尽量原调」而不是简单粗暴地全部折返。

## 8. 时序与调度层设计

### 8.1 音乐时钟

```text
目标时刻 = t0 + 谱面时间 / speed
```

- `t0` 每轮循环开始时重置（循环播放会重新计时）。
- 等待期间暂停时，把暂停时长加入 `t0`。音符进行中暂停时先松键，恢复后重新锚定时间轴到该音符起点，重新演奏这一音。
- 调度每轮等到曲谱终点。循环时在曲末再等待 0.8 秒后重置 `t0`。
- Windows 后端在播放会话请求 `timeBeginPeriod(1)`，成功后在会话结束时成对调用 `timeEndPeriod(1)`。

### 8.2 单音时序

```text
确认当前时间窗容得下预备和最短保持
按下修饰键（若有），每次发送前复查停止与前台状态
等待 PREP_MS = 12ms，复查状态和剩余时间
按下音键
release_at = min(音符终点, max(音符终点 − 20ms, 实际按下时刻 + 40ms))
等待到 release_at（期间处理暂停/失焦/停止）
松开音键
按相反顺序松开修饰键
```

- 尾隙可吸收迟到。预备或最短保持时间放不下时跳过该音，后续起点仍按绝对时间调度。
- 每个音符结束都释放修饰键，避免在按住音键时改变修饰键触发重新发声。
- `finally` 块保证任何异常路径都会尝试松开音键和修饰键。
- 演奏线程独占输入后端，UI 和热键线程只提交取消或暂停请求。结束时由演奏线程尝试 `release_all()`，释放失败会记入日志。

### 8.3 状态机

```text
idle ──play──> countdown ──> playing ──finish──> finished ──> idle
                                 │  ↑
                         失焦    ▼  │ 恢复
                            waiting_game
                                 │  ↑
                         手动暂停 ▼  │ 继续
                              paused
任意活动状态 ──stop/急停/异常──> idle（释放所有输入）
```

- 状态变化通过回调推送到 UI，UI 依据状态启停按钮。
- `countdown` 期间停止会立即取消，不会留下按键。
- 失焦与手动暂停共用暂停逻辑：释放按键、冻结音乐时钟、状态提示。

### 8.4 进度与日志

- 每个音符开始前回调 `(index, total, note)`，UI 显示「第 i/N 音 · 按 X（修饰）」。
- 日志覆盖：环境与权限、热键注册结果、移调统计、跳过音符数、暂停原因、结束/停止/错误。

## 9. 输入层设计

### 9.1 SendInput

- 键盘：只发送扫描码，`KEYEVENTF_SCANCODE`，按下/松开分别不带/带 `KEYEVENTF_KEYUP`。扫描码比虚拟键更接近物理键盘，兼容性更好。
- 鼠标：按下/松开使用 `MOUSEEVENTF_LEFTDOWN/UP`、`RIGHTDOWN/UP`、`MIDDLEDOWN/UP`。
- 每次调用 `SendInput` 必须返回 1，否则抛出带排查建议的 `RuntimeError`（权限不一致、输入法、窗口模式）。
- 使用 `ctypes` 直接声明结构体和 `argtypes`，不依赖 `pywin32` 等第三方库。

### 9.2 按键跟踪与释放

- `Win32Backend` 维护 `_held_keys` 与 `_held_buttons`。
- `release_all()` 仅处理后端记录为按下的键。
- 松开失败时保留记录，允许后续再次尝试。

### 9.3 前台检测

```text
GetForegroundWindow
  → GetWindowThreadProcessId
  → OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)
  → QueryFullProcessImageNameW
  → basename
```

- 启用前台保护时，空关键字会阻止开始演奏。首次匹配进程名时锁定前台窗口句柄和 PID。
- 绑定后只比较当前前台窗口的句柄和 PID。等待和发送按下事件前均复查，回到原窗口时才能自动继续。
- UI 每秒刷新一次前台进程显示，便于排查关键字配置。

### 9.4 DryRun

- `DryRunBackend` 所有输入方法为空操作。
- 默认使用。Windows 上可关闭「仅测试」，非 Windows 平台固定启用。
- 用途：验证曲谱解析、映射、时序、UI 状态机，不接触游戏。

## 10. 安全设计

威胁与对策：

| 风险 | 对策 |
|---|---|
| 用户点播放后还没切回游戏就开始按键 | 3 秒倒计时 |
| 演奏中切出游戏导致按键落到其他窗口 | 绑定窗口句柄和 PID，失焦时暂停并释放 |
| 程序异常/停止时按键卡住 | 演奏线程在 `finally` 中清理，后端记录待释放输入 |
| 急停热键被占用，用户无法停止 | `Shift+F8` 注册成功才允许真实演奏，演奏中热键失效会请求停止 |
| 误在开发机/无游戏环境发送按键 | 默认 DryRun，Windows 用户可主动关闭「仅测试」 |
| 权限不一致导致 SendInput 静默失败 | 启动显示权限；失败时抛出带提示的错误 |
| 播放热键与游戏按键冲突 | 三组播放热键使用 Shift 前缀，全局热键使用 `MOD_NOREPEAT` |
| 退出程序留下按键 | `closeEvent` 请求停止，等演奏线程清理后关闭 |

边界说明：如果进程被强制杀死（任务管理器/崩溃），Windows 不会自动替应用发送 keyup，可能留下逻辑按下的键；此时手动按一下对应键或切出游戏即可恢复。这是所有模拟输入方案的共同限制。

## 11. 热键设计

- Windows 通过 `RegisterHotKey` 将热键注册到独立线程的消息队列。三组播放热键带 `MOD_SHIFT`，切换悬浮窗的 `F11` 使用单键。
- 线程启动时先 `PeekMessage` 创建队列，再 `GetMessage` 循环分发 `WM_HOTKEY`。
- 退出时通过 `PostThreadMessage(WM_QUIT)` 结束循环并注销热键。
- 注册结束时主动通知 UI，按注册结果报告可用性。
- 普通热键通过 Qt 信号交给主线程。急停热键直接请求演奏线程取消，日志仍通过 Qt 信号输出。
- 全局 `F11` 不可用时，Qt 快捷键在主窗口有焦点时打开悬浮窗。悬浮窗上的「主窗口」按钮可展开完整界面。

选择 `Shift+F9/F10/F8` 的原因：

1. 避开游戏常用的 `F1`–`F12` 单键和 `Alt` 组合；
2. 三键分布在键盘左侧，单手可及；
3. 不与常见输入法切换冲突（`Shift` 单独切换输入法不会触发组合键）。

## 12. UI 设计

- 主窗口左侧为曲库与曲谱摘要，右侧为演奏控制、前台与输入和运行日志。演奏区显示当前曲名、当前音符与进度条，底部状态栏显示运行环境。
- 曲谱解析在后台线程执行。UI 按路径、修改时间和文件大小缓存近期解析结果，并根据速度、移调与自动适配更新计划。
- 主窗口的播放设置和曲库在倒计时、等待窗口、演奏与暂停期间锁定。活动状态下可以停止播放或从浮窗选曲。
- 选曲窗口支持多选文件，也可拖入多个曲谱。导入保留曲库已存在的同名文件。
- 主窗口与悬浮窗共用 `ui/theme.py` 的深石墨蓝色板。冰蓝用于主操作和进度，琥珀用于暂停和等待状态。
- 冻结（PyInstaller）时曲库目录取 exe 所在目录的 `scores/`，避免写入临时解包目录。

### 12.1 悬浮窗

- 主窗口和悬浮窗共用曲库、当前选择、播放状态与进度。浮窗的「选曲」展开可滚动的曲库列表。
- 有播放会话时，选中另一首曲目先请求停止，待当前会话清理后再切换。切换完成后由用户点击播放。选中当前曲目保留当前状态。
- 悬浮窗使用 Qt 置顶和非激活标志，显示和操作时尽量保留游戏前台焦点。窗口支持拖动和返回主窗口。
- 浮窗显示 0%–65% 的透明度，默认 15%，向右拖动更透明。主窗口显示 `100% − 透明度` 的不透明度。两个控件同步，本机继续保存不透明度与浮窗位置。

## 13. 打包

`build_exe.bat`：

```bat
python -m pip install -r requirements.txt pyinstaller
python -m PyInstaller --noconfirm --clean --windowed --name HarmonicaPlayer main.py
xcopy /E /I /Y scores dist\HarmonicaPlayer\scores
```

- `--windowed`：不显示控制台；日志在 UI 内。
- 默认 one-folder 模式，升级/替换资源方便。
- `scores/` 放在 exe 同级目录，用户可自由增删曲谱。
- 冻结判断：`getattr(sys, 'frozen', False)` 时使用 `Path(sys.executable).parent / 'scores'`。

## 15. 设计取舍

1. **统一尾隙 20ms**。MIDI 和 TXT 使用同一尾隙，给相邻音符留出间隔。实机校准时可调小 `DEFAULT_GAP_MS`，并重新验证最短时长。
2. **高层单音化而非轨道选择**：MVP 优先「任意 MIDI 能直接弹」，用最高音启发式近似主旋律；后续可增加轨道选择或旋律检测。
3. **整体移调优于逐音折叠**：保持旋律轮廓，减少八度跳变；代价是整体可能升降调。
4. **ctypes 手写 SendInput**：依赖少、行为透明，也不引入第三方输入库；代价是需要自行维护结构体定义。
5. **PySide6 而非 tkinter**：需要深色主题、状态栏、日志面板和更接近原生桌面工具的观感；代价是打包体积较大。
6. **Shift 前缀热键**：牺牲一点按键便利性，换取与游戏按键的低冲突概率。
7. **确认急停热键注册**：真实演奏要求 `Shift+F8` 可用，注册冲突时仍可试运行。
8. **固定 3 秒倒计时**：实现简单、可预期；后续可做成设置项。
